# 裝不下的時候，代價是什麼

[English](spill-cost.md) · **繁體中文**

這裡其他每一頁都預設「目標是把整個模型留在顯存裡」。
這一頁談的是：如果沒有做到會怎樣，以及為什麼那個前提一開始就值得堅持。

## 簡短版

同一張卡、同一個模型、同一種量化。唯一改變的是「有多少裝進顯存」：

| | 生成速度 |
|---|---|
| 65 層全部在顯存 | 約 26 tok/s |
| 65 層中只有 28 層在顯存，其餘在系統記憶體 | **5.11 tok/s** |

**溢出 57% 的層，速度慢了五倍。**

llama.cpp 會很樂意幫你做這件事。把 `-ngl` 設得比層數小，
或乾脆讓它自己退讓，它照跑不誤 —— 只是速度剩一小截，
而且不會有任何錯誤訊息告訴你原因。

## 為什麼會這麼慘

住在系統記憶體裡的層，**每一個 token** 都得跨過 PCIe 匯流排去取。
這張卡的顯存跑在 448 GB/s；PCIe 5.0 x8 理論上限約 32 GB/s，實際還更低。
這個落差就是全部的原因。

而且這件事沒辦法用更快的 CPU 或更多記憶體遮掉。
瓶頸在那條連結本身，不在它另一端的記憶體或算力。
換更快的 DDR 不會解決，插更多通道也不會。

這就是為什麼「**裝得下**的最大量化勝過裝不下的更好量化」
是 [model-quant.zh-TW.md](model-quant.zh-TW.md) 的第一條規則。
往上跳一階的量化也許替你換到幾個百分點的品質，
溢出則是直接吃掉你 80% 的速度。

## 怎麼量一張你沒有的顯卡

上面的數字來自一張 RTX 5060 Ti 16GB「假扮」成 8GB 版本。
這個替代在這裡是站得住腳的，理由很具體：兩個版本是
**同一顆 GB206 die、同樣 4608 個 CUDA 核心、同樣時脈、
同樣的 128-bit GDDR7 448 GB/s**。
規格表上唯一的差別就是容量，所以限制大卡就能相當接近地重現小卡。

**借用這個技巧之前請先確認這件事。** 大多數推出兩種容量的卡，
會連記憶體位寬一起砍 —— RTX 3060 的 12GB 和 8GB 版本位寬就不同，
所以把 12GB 卡限制起來並不能告訴你 8GB 版本的表現。
先確認同一顆 die、同樣核心數、同樣頻寬。

方法是用另一個 CUDA 程序佔住顯存
（[tools/hold-vram.py](../tools/hold-vram.py)），
讓受測的那一輪只看得到較小的預算：

```bash
# 留下 7800 MiB —— 大約是真實 8GB 卡的可配置預算
python tools/hold-vram.py 7800 &
ctxprobe model.gguf --ngl 28 --list 4096
kill %1
```

用這個方式產出的任何報告，都有兩點該一併說明：

- **驅動保留區不同。** 這裡的 16GB 卡保留 462 MiB，8GB 卡保留得更少。
  以「剩下 7800 MiB」為目標是個估計值，而且是偏保守的那一側。
- **`nvidia-smi` 的數字包含佔用程序。** 要看模型自己的用量得把它減掉。
  `ctxprobe` 會另外回報剩餘顯存，就是為了這個原因。

## 8GB 這個案例實際顯示了什麼

| `-ngl` | 在 GPU 上的層數 | 結果 | Prefill | 生成 |
|---|---|---|---|---|
| 999 | 全部 65 層 | **LOAD_FAIL** | — | — |
| 32 | 32 | **LOAD_FAIL** | — | — |
| 28 | 65 層中的 28 層 | PASS | 391 tok/s | 5.11 tok/s |
| 24 | 65 層中的 24 層 | PASS | 368 tok/s | 4.63 tok/s |

27B 的 `IQ4_XS`（15.44 GB）在 8GB 卡上，以任何堪用的標準來說都裝不下。

到這一步的直覺反應是去換更小的量化 —— 而這個直覺在這裡是錯的。
`Q3_K_M` 是 13.59 GB，`IQ3_XXS` 是 11.99 GB，兩個一樣裝不下，
而且兩個都是明顯更差的模型。
**「27B 塞不進我的 8GB 卡」的答案是換更小的模型，不是換更小的量化。**
14B 的 `Q4_K_M` 就能裝得下、還有空間留給 context，而且是全速執行。

## 什麼時候溢出其實沒關係

它不總是錯的選擇：

- **你要的是大模型的能力，而不是速度**，而且 5 tok/s 對你的用途可以接受。
  人的閱讀速度大約就是 5 到 10 tok/s，所以這不是自動等於不能用 ——
  它是對任何 agent 類或長篇產出不能用。
- **MoE 模型。** 每個 token 只有一小部分參數會被啟用，
  所以把 expert 放在系統記憶體（`--n-cpu-moe`）的代價，
  遠低於把 dense 層溢出。那是另一種取捨，跟這裡量的不是同一回事。

真正不行的是**不小心**溢出 —— 而那才是常見情況，因為沒有任何東西會通知你。
去看啟動 log 裡的層數，或是直接跑 `ctxprobe`，
它不會把「部分 offload」算成通過。
